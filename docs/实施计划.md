## 2. 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Go 1.22+，`net/http` + chi |
| 查询 | sqlc + goose 迁移 |
| 数据库 | SQLite（`modernc.org/sqlite`，纯 Go 无 cgo） |
| 实时通信 | `coder/websocket` |
| 前端 | Vue 3 + Vite + TypeScript，`go:embed` 打进二进制 |
| 流媒体 | MediaMTX |
| 录制/切片 | FFmpeg（TS/fMP4 分段，导出转 MP4） |
| 部署 | 单 exe + MediaMTX + FFmpeg，Windows 服务运行 |

## 7. 机位接入最低要求

| 参数 | 最低要求 | 门线位建议 |
|---|---|---|
| 分辨率 | 1920×1080 | 4K |
| 帧率 | 25fps | 50fps |
| 快门 | ≤1/250s | ≤1/500s |
| 编码 | H.264 | H.264 |
| 码率 | 4 Mbps | 8 Mbps |
| 视场 | 全景位覆盖半场 | 覆盖 10–15 米 |
| 音频 | 有更好（用于同步） | 有 |
| 对时 | NTP 或允许偏移校准 | 同左 |

> 帧率、快门、视场三项不达标会直接削弱复核能力，属甲方设备责任，不作为软件验收缺陷。

## 8. 主要风险

| 风险 | 应对 |
|---|---|
| 单人串行，任一模块超期直接顺延 | 15% 缓冲；砍功能顺序：AI → 远程分享 → 多场次统计 |
| 摄像机参数未知，W1 卡住 | 先用 FFmpeg testsrc 生成 6 路测试流开发 |
| Windows 防火墙/杀软拦端口 | 打包时预置防火墙规则，固定端口 |
| 录制盘写满 | 水位低于 15% 自动清理最旧片段并告警 |
| 6 路回看不同步 | 偏移量存库、手动/音频校准，不依赖摄像机时钟 |

## 9. 验收标准

1. 6 路同时录制，连续 2 小时无中断，磁盘写入正常。
2. 打点后 60 秒内生成 6 路片段。
3. 6 路回看可同步定位到同一时刻，误差 ≤1 帧。
4. 证据包包含 6 路片段、事件清单、SHA-256 校验值。
5. 两场试运行无阻断性缺陷。
